This experimental patch fixes the shared journal's16-character rejection and
destructive restore path. It also corrects native café filename truncation in
the original AddNote/NoteDoc interfaces, preserves rejected native records and
adds bounded per-client delivery/resource diagnostics and shared notifications.
Static documents and virtual code notes keep their own native behavior.

All eight BSPs are byte-identical to the user's tested maintenance candidate.
Readiness, the working automatic intro exit, nightmare/wake/equipment, doors,
canonical puzzle values, pickups and checkpoint code are retained. The record
format and checkpoint version are unchanged. Journal capacity remains16; no
live document handle is saved. Recipient iteration supports the engine's client
count; the new fixture covers four clients. Four-player gameplay and four-active
checkpoint saving remain unverified/unsupported respectively.

The vehicle remains unresolved. New native Spawn/render/PVS/packet evidence
replaces further speculative map edits. Use the single test in TESTING.md and
retain both complete logs even if the vehicle remains invisible; continue to the
note rows when intro progression works. DIAGNOSTICS.md explains the supplied log,
root-cause evidence, exact café entities and remaining uncertainty.

NOTE_AUDIT.json checks all195 existing aliases and their81 source maps without
regenerating them. QA.json records executed checks. No original BSP/DLL, Steam
authentication or liblist change occurs. Installation uses the existing guarded
installer and `-dll cl_dlls/storycoop_rc4.dll`; no compiler is required.

Use START_HERE.md for PowerShell install and rollback commands. Keep the entire
retained maintenance package for reinstall. Operational journal UI/notifications,
